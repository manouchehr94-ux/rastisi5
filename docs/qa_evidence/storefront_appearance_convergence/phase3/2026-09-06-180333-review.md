### CSS carousel fix mirrors home.css and is a verified Home no-op

The whole production surface of Task 5 is this block appended to `storefront_builder.css`:

```css
.collection-tiles-carousel.tiles-carousel .pcard{flex:0 0 220px;scroll-snap-align:start}
@media(max-width:680px){
  .collection-tiles-carousel.tiles-carousel .pcard{flex-basis:180px}
}
```

home.css defines exactly one governing block for the same selector (lines 83–85: `flex:0 0 220px;scroll-snap-align:start` plus `@media(max-width:680px){flex-basis:180px}`), with no later override, so those literals are the cascade-resolved values on Home. `grep` confirms there is a single such block; the only other `tiles-carousel` rules in home.css target `.tile`, not `.pcard`. Because the Builder sheet loads after home.css on the Home envelope, carrying identical values makes the override a no-op — the Task-3 lesson (a value mismatch silently shifting Home) does not recur here (confirmed). On the four non-Home envelopes that load the Builder sheet but not home.css, the rule supplies the previously-missing carousel tile sizing. The selector is anchored on `.collection-tiles-carousel`, so the grid variant's `.pcard` sizing (from product_card.css) does not spill (confirmed).

This contract is not left to inspection — `CollectionCarouselCssIsInSharedBuilderStylesheetTests` reads both real stylesheets and asserts the selector is present in the Builder sheet, the 220px/180px values match home.css's governing block, home.css's rule is not deleted, and every rule inside the delimited Collection block is `.collection-tiles-carousel`-scoped (no global `.pcard` spill). All five pass (confirmed).
